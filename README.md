# sqlexpr-load-rust

A load testing harness for the [sqlexpr-congo-rust](https://github.com/richcar58/sqlexpr-congo-rust) library, designed to evaluate the performance of boolean SQL expression parsing and evaluation at scale.

## Overview

This project provides comprehensive performance testing capabilities for the sqlexpr-rust library by:
- Loading and evaluating large numbers of pre-generated boolean SQL expressions
- Measuring execution times with microsecond precision
- Grouping results by expression complexity (number of AND/OR operators)
- Computing statistical metrics including min, max, average, and standard deviation
- Generating detailed markdown reports for analysis

The harness reads test data from an input JSON file (default: `resources/complex_expressions-max.json`) containing expressions generated by [sqlexpr-gen](https://github.com/richcar58/sqlexpr-gen), times each evaluation, and outputs comprehensive statistics organized by complexity class.  The `resources/complex_expressions-limited.json` test data file is provided for parsers that do not accept certain, non-standard language constructs, such as upper and lower bounds in BETWEEN clauses of type String.

**Repository**: https://github.com/richcar58/sqlexpr-load-congo-rust

The project is a part of a suite of production-ready and experimental projects that provide SQL-based boolean expression parsers and evaluators that use different technologies in their construction and output.  Below is a summary of these projects.

**NOTE:** The first Rust parser/evaluator, **sqlexpr-rust**, was generated by Claude directly from an EBNF grammar.  Load testing in *sqlexpr-load-rust* reveals that this implementation was actually **slower** than the handcrafted Java parser generated by CongoCC (**sqlexpr-congocc**).  The second Rust parser/evaluator, **sqlexpr-congo-rust**, was generated using CongoCC enhanced to directly output Rust parsers.  Load testing in *sqlexpr-load-congo-rust* results in an approximate 2.5% improvement over the CongoCC-generated Java parser (in non-scientific testing).  Further performance improvements can probably be wrung from the improved Rust parser, but it's clear that a well-designed, well-written Java parser is quite competitive in certain testing scenarios.   

## Input Data

The test expressions are read from:
- **File**: `resources/complex_expressions-max.json`
- **Format**: JSON array of objects, each containing:
  - `expr`: A boolean SQL expression string (e.g., `"(s69 <= 'banana') OR (s57 < 'banana')"`)
  - `value_map`: A HashMap of variable bindings (e.g., `{"s57": "a", "s69": "bananaz"}`)

**NOTE:** The *resources/complex_expressions-max.json* default input file exercises an extended SQL syntax, whereas *resources/complex_expressions-limited.json* exercises standard SQL syntax.  For example, the extended syntax accepts both numbers and strings in IN lists; standard syntax accepts only strings in IN lists.

## Building the Project

### Prerequisites
- Rust toolchain (1.89 or later recommended)
- Cargo package manager

### Compile Commands

```bash
# Debug build (includes debug symbols, faster compilation)
cargo build

# Release build (optimized, recommended for actual load testing)
cargo build --release
```

The compiled binary will be located at:
- Debug: `target/debug/sqlexpr-load-congo-rust`
- Release: `target/release/sqlexpr-load-congo-rust`

## Running the Load Tests

### Basic Usage

```bash
# Run with default settings (1 iteration per expression)
cargo run

# Run release build for optimal performance
cargo run --release

# Run with custom iteration count
cargo run --release -- --iterations 100
```

### Command Line Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `--iterations` | usize | 1 | Number of times to evaluate each expression (must be ≥ 1) |
| `--input` | String | `complex_expressions-max.json` | Input file path (absolute or relative to resources/ directory) |

### Examples

```bash
# Single evaluation of each expression (fastest, good for syntax validation)
cargo run --release -- --iterations 1

# 100 iterations per expression (good for initial performance testing)
cargo run --release -- --iterations 100

# 1000 iterations per expression (comprehensive performance analysis)
cargo run --release -- --iterations 1000

# Use a different file from resources/ directory
cargo run --release -- --input complex_expressions-limited.json

# Use absolute path
cargo run --release -- --input /path/to/custom/expressions.json

# Combine with iterations
cargo run --release -- --iterations 100 --input complex_expressions-limited.json
```

## Output

The harness generates markdown reports in the `output/` directory:

### test_timings.md
Contains comprehensive statistics for each complexity class:
- **Overall Statistics**: Timestamps, iteration count, total expressions, evaluations, execution time, and failure count
- **Results by Complexity Class**: Detailed timing tables showing total time, min, max, average, and standard deviation in milliseconds

Example output:
```

- **Start Time (UTC)**: 2025-12-18 15:09:38 UTC

- **Iterations**: 100
- **Total Expressions Evaluated**: 10000
- **Total Evaluations Executed**: 1000000
```

### failed_tests.md
Created only if evaluation errors occur. Contains:
- Expression that failed
- Variable bindings (value map)
- Error message

## How It Works

1. **Load**: Reads test expressions from `resources/complex_expressions-max.json` by default
2. **Calculate**: Determines complexity class for each expression (count of AND/OR operators)
3. **Evaluate**: Runs each expression N times (specified by `--iterations`)
4. **Time**: Measures execution duration with microsecond precision
5. **Aggregate**: Groups timing data by complexity class
6. **Analyze**: Computes statistical metrics (min, max, avg, stdev)
7. **Report**: Generates markdown files with formatted results

## Key Concepts

- **Expression Complexity**: The number of logical OR (disjunction) and AND (conjunction) operators in a boolean expression
- **Complexity Class**: A grouping of all expressions with the same complexity value
- **Iteration**: A single evaluation of an expression; multiple iterations provide more reliable timing statistics
